# I18N — internationalisation EN/FR

> Créé le 2026-09-06 (chantier « app bilingue », commit `1108ab3`). Décrit **comment** l'app est
> traduite et **comment ajouter une chaîne** sans réintroduire de texte en dur. Référence vivante :
> à mettre à jour si le mécanisme change (ajout d'une 3ᵉ langue, migration `RadioGroup`, etc.).

## Ce qui est en place

- **`flutter_localizations`** (SDK) + **`intl`** (déjà présent).
- **`generate: true`** dans `pubspec.yaml` (bloc `flutter:`) et **`l10n.yaml`** à la racine :
  ```yaml
  arb-dir: lib/l10n
  template-arb-file: app_en.arb        # l'anglais est le TEMPLATE (porte les @-métadonnées)
  output-localization-file: app_localizations.dart
  output-class: AppLocalizations
  nullable-getter: false               # AppLocalizations.of(context) est NON nullable
  ```
- **Sources de vérité** : `lib/l10n/app_en.arb` (template, avec les `@clé` de placeholders/pluriels)
  et `lib/l10n/app_fr.arb`. **~90 clés.**
- **Fichiers générés** : `lib/l10n/app_localizations.dart` (+ `_en`, `_fr`). Ils sont **versionnés**
  (committés) pour que l'arbre soit autonome sur un clone neuf — ne pas les éditer à la main.
- **Câblage** (`lib/main.dart`) : `localizationsDelegates: AppLocalizations.localizationsDelegates`
  (inclut déjà les délégués Material/Cupertino/Widgets globaux), `supportedLocales:
  AppLocalizations.supportedLocales`, et `locale:` résolu depuis les réglages.
- **Choix de langue** : champ **`AppSettings.localeCode`** (`String?`, JSON → **pas de migration**,
  invariant #6). `null` = suit la locale de l'appareil (défaut) ; `'en'`/`'fr'` = forcé. Setter
  `SettingsNotifier.setLocale`. **Sélecteur `Système / Français / English`** dans l'écran Réglages
  (`_showLanguageDialog`). Le `MaterialApp` fait `locale: code == null ? null : Locale(code)`.

## Ajouter / modifier une chaîne visible — la procédure

1. Ajouter la clé dans **`app_en.arb`** (template) **et** `app_fr.arb`. camelCase, groupée par écran.
   - Placeholder : `"levelLabel": "Level {level}"` + dans le template
     `"@levelLabel": { "placeholders": { "level": { "type": "int" } } }`.
   - Pluriel : `"piecesCount": "{count, plural, one{{count} piece} other{{count} pieces}}"`
     (+ `@`-metadata `count:int`). **Le français a ses propres règles** (`one` couvre 0 et 1).
2. **Régénérer** : `flutter gen-l10n` (ou n'importe quel build). Ne pas oublier après toute
   édition d'ARB.
3. Utiliser dans le widget : `final l10n = AppLocalizations.of(context);` puis `Text(l10n.maClé)`
   / `l10n.piecesCount(n)`. Enlever le `const` du `Text`/widget parent au besoin.
4. `flutter analyze` (0 error attendu) — une clé oubliée dans un ARB ou un placeholder mal typé
   sort ici.

## Pièges rencontrés (et le motif de contournement)

- **Un `const` ne peut pas appeler `AppLocalizations`** (pas de `context`). Deux cas concrets :
  - `game_icons_config.dart` : les `GameIconConfig` sont `static const` avec un `tooltip` français
    baké. On **ne les traduit pas dans le config** ; on résout au **site d'usage** (barre
    d'isométrie de `pentoscope_game_screen.dart`) via `l10n.isoRotateTW`… Le champ `tooltip` du
    config reste (contrat du constructeur) mais **n'est plus affiché**.
  - `leaderboard_screen.dart` : la liste `const _maillots` ne porte **plus** le libellé ; il est
    résolu par le helper `_maillotLabel(l10n, maillot)` (mêmes trois mots que la légende des
    records). Motif général : **stocker l'enum/la couleur en const, résoudre le texte au build**.
- **Helpers sans `context`** : pour un widget `StatelessWidget`/`State`, `context` est disponible
  dans `build`/les méthodes d'instance. Pour une **méthode statique ou libre** qui compose une
  chaîne, **passer `AppLocalizations l10n` en paramètre** (ex. `_buildMyRankCard`,
  `_buildRankingsList` dans `pentoscope_mp_result_screen.dart`).
- **Dialogues** : le `builder:` d'un `showDialog`/`showModalBottomSheet` reçoit **son propre
  `context`** — y faire `AppLocalizations.of(ctx)`. Plusieurs `=> AlertDialog(...)` ont été
  convertis en corps de bloc `{ final l10n = …; return AlertDialog(…); }`.

## Volontairement laissés littéraux (par choix, pas par oubli)

- **`PENTAPOL`** (logo de l'accueil), **`Pentoscope Multiplayer`** (nom du mode) — noms propres.
- **`Go`**, **`DNF`**, **`GO!`** — abréviations universelles.
- Le **SnackBar de debug « 🎯 Lobby chargé - test DB »** (`pentoscope_mp_lobby_screen.dart`,
  `initState`) — artefact de développement, à **retirer** plutôt qu'à traduire (dette, cf.
  `CHECKLIST_APPSTORE.md`).
- Les **libellés `DuelDuration`** (`app_settings.dart` : « 1 min »… numériques ; « Perso »
  n'apparaît jamais à l'écran — le seul chip filtre `custom`). Si un jour ils doivent être
  traduits, il faudra les résoudre au site d'usage (le modèle n'a pas de `context`).

## Ajouter une 3ᵉ langue (esquisse)

1. `lib/l10n/app_<xx>.arb` avec **toutes** les clés du template.
2. `flutter gen-l10n` (la locale est détectée automatiquement, `supportedLocales` se met à jour).
3. Ajouter l'entrée au sélecteur de langue (`_showLanguageDialog` + `_languageName` dans
   `settings_screen.dart`) et une clé `language<Xx>`.
